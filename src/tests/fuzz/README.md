# LibMP fuzz harnesses

libFuzzer targets for LibMP's untrusted-input surfaces, built with Clang + ASan + UBSan.
They are the continuous-fuzzing counterpart to the deterministic tests in `src/tests/cpp/`.

## Targets

| Harness | Exercises | Threat surface |
|---------|-----------|----------------|
| `control_channel` | `LibMP::ControlChannel::OnCommand` with mock host callbacks | `MicroProfilerService:ProcessCommand` |
| `getdatainrange` | `LibMP::ReadDataInRange` against a `DataContextMemChunks` | `MicroProfilerService:GetDataInRange` |
| `gprx_reader` | `MpOpenFromMem` + the full reader/iterator C API | offline `.gprx` parsing |
| `codec` | LZ4 and Base64 stream decoders on arbitrary bytes | container payload decompression |

Each harness checks invariants directly (response never exceeds the offered capacity,
guard bytes around output buffers stay intact, callbacks fire only on success) in
addition to what ASan/UBSan catch.

## Build and run

```sh
python3 src/tests/fuzz/build_fuzz.py                 # build all harnesses (ASan+UBSan, assertions ON)
python3 src/tests/fuzz/build_fuzz.py --smoke         # replay generated and optional local seeds
python3 src/tests/fuzz/build_fuzz.py --replay        # also replay the persistent working corpus
python3 src/tests/fuzz/build_fuzz.py --run 30m       # fuzz all targets concurrently for 30 minutes
python3 src/tests/fuzz/build_fuzz.py --run 2h --workers 2
python3 src/tests/fuzz/build_fuzz.py --no-assert     # build with assertions disabled
python3 src/tests/fuzz/build_fuzz.py codec --run 1h  # run a single harness
python3 src/tests/fuzz/build_fuzz.py --merge         # minimize persistent corpora
```

Binaries and generated seeds are kept in `src/build/fuzz/{assert,no-assert}`.
Optional local seeds may be placed under `src/tests/fuzz/corpus/<target>`; this directory
is gitignored and is not regenerated by the runner. Campaign corpora, crash artifacts,
logs, and JSON summaries persist separately in `src/build/fuzz-state`, so `--clean` does
not discard findings. During a fuzzing campaign, the persistent corpus is writable;
generated and optional local seeds are additional read-only inputs.

All selected targets run concurrently, while `--workers` controls independent workers
per target. `--run` accepts seconds or an `s`, `m`, or `h` suffix. Use `--state-dir` to
place persistent state elsewhere, `--reset-corpus` to discard learned inputs, and
`--fuzzer-arg=<option>` for additional libFuzzer options. Safety and bookkeeping
options managed directly by the runner cannot be overridden this way. A failing worker
stops the other workers after they have saved their current corpora.

## Corpus maintenance after format changes

The deterministic seeds under `src/build/fuzz/{assert,no-assert}/seeds` are deleted and
regenerated from `make_seed_corpus.cpp` on every runner invocation. This includes the GPRX
reader seed rebuilt from the current `roundtrip_capture_data.inc`; do not maintain or wipe
that generated directory manually.

After changing a harness input layout, the GPRX format, the reference capture data, or the
FlatBuffers schema:

1. If the schema changed, regenerate its checked-in sources and command registry with
   `python3 src/scripts/gen_flatbuffers.py --cpp`.
2. Regenerate and replay the deterministic seeds in both assertion modes:

   ```sh
   python3 src/tests/fuzz/build_fuzz.py --smoke
   python3 src/tests/fuzz/build_fuzz.py --no-assert --smoke
   ```

3. Run `--replay` to check the persistent learned corpus against the new reader, then run a
   fresh fuzz campaign. Keep the old corpus when compatibility is expected: previously valid
   inputs and newly malformed inputs are useful regression coverage.
4. Run `--merge` after a successful campaign when the persistent corpus has grown large.

Use `--reset-corpus` only for an intentionally incompatible input-model change or when the
old learned corpus is no longer useful. After resetting, run `--smoke` and a fresh campaign
to repopulate coverage. Resetting the corpus does not delete saved crash artifacts or logs.

To minimize a reproducer:

```sh
python3 src/tests/fuzz/build_fuzz.py gprx_reader \
    --minimize-crash src/build/fuzz-state/artifacts/gprx_reader/crash-...
```

Every crash or timeout reproducer should be minimized and turned into a
`src/tests/cpp/` regression case. Campaign summaries record seeds, duration, exit status,
coverage counters, corpus growth, artifacts, and logs for later reproduction.

## Requirements

- Clang with libFuzzer (`clang++-18` or `clang++`). The script discovers the compiler and
  newest installed GCC support directory; all choices can be overridden with
  `LIBMP_FUZZ_CLANGXX` and `LIBMP_FUZZ_GCC_INSTALL_DIR`.
- `vptr`/`function` UBSan checks are disabled because LibMP is built without RTTI; the
  value checks (integer overflow, out-of-bounds, alignment, shifts) remain active.
